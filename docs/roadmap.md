已知限制与未来方向（非本轮待办，记录认知供后续设计）：
- **调车/倒车能力缺失**（2026-09 #1 验收反馈记录）。连挂/解挂已完成，但
  编组作业局限在"前进对接 + 原方向驶离"：
  - **无物理倒车**：`advance_occupied_path` 只沿 route 正向推进，没有负向
    （倒车）推进原语。
  - **无玩家手动掉头入口**：键盘没有任何"原地折返"键。折返只在两种情况
    自动发生——寻路路径含折返边时到端点触发（仅死端 simple_segment 端点，
    `pathfinding.neighbors` 从 `connection_count==1` 节点插入掉头边）、或
    `_apply_route_result` 首边不匹配时自动 reverse。`reverse_in_place` 本身在
    环线/直线中段**也能**掉头（内部用 `truncate_to_segment` 截断，实测环上
    占用单边时成功、车头正确反转），但玩家没有入口主动触发它。
  - 因此 AB 顺序相连解挂后，A 在 B 前方想"倒出去"（沿 -x 退回）时：玩家
    没有掉头键让 A 先转向，只能沿原方向（+x）寻路——若前方是 B，无碰撞
    模型下表现为"碾过去"（视觉穿过，非碰撞）。
  - 判定：这是**预期内结果，非 bug**——几乎所有铁路游戏都简化或回避调车
    （OpenTTD 无连挂；Transport Fever 用机车头自动对接简化）。本项目 demo
    阶段接受此限制；将来若做真实调车（侧线脱离 / 顶推 / 倒车入位），需要
    先补"负向推进（倒车）原语"或"玩家手动掉头入口"，再谈交互。
