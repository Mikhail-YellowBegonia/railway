## 0. 项目目标与收口条件（当前口径）

- **demo 收口 = 计划式自动驾驶落地 + 项目开源**（`docs/roadmap.md` #7 / #8）。
- **demo 不做**：真实物理扩展（#3）、LOD（#4）、瓦片化（其实已实现）、**货物/装载**（#10）。
- **有意取舍不修**：无物理倒车（负向推进原语）、无碰撞模型（A 碾过 B 是视觉穿过）。
- 编辑器（Steps 0–6 + 吸附 + 空间索引）与信号系统（Step 1–6）**已完成并人工验收**；
  #1 连挂/解挂（含折返/寻路联合场景）与 #2 会话持久化**已人工验收通过**。

## 1. 当前在研究什么（一句话）

让列车"**按计划自动运行**"：**计划归控制车（车厢）所有**（"每个控制车都有一个司机，
有自己的任务，与列车无关"），编组每帧**遴选**并**投影**成 `route`/`goal`，
目标点用 **POI**（最小可行范围 = 只做"有向点"）表达。

## 4. 待研讨（按优先级）

1. **POI 建模**（roadmap #9 第 2 项；MVP 已定，细节未定）：`docs/poi.md` §7 的

   O3 属性面、O4 放置交互、O5 id 与落盘、O6 与信号/block 的关系、O7 路段多目标、O8 远期两类。
2. **计划/命令类型**（roadmap #9 第 3 项）：机制已定（Q13/Q14/Q15/Q16），**内容未定**——
   有哪些命令？"等待…"有多少种？**demo 是否纳入连挂/解挂命令**？
   **调研后收敛为三个具体问题**（`research_pxpatch.md` §5/§6 + `wagon_centric_data.md` §5 Q17）：
   - **Q17-1 跳转目标**：用"下标"（px-patch 的做法）还是"标签"（新增原语）？
     **文档侧倾向：表内下标 + 跨计划用 ID**（他们的玩家手册都写"总是跳至第二项"）。
     ⚠ 连带：**"3 空命令"是否需要存在，取决于这一问**——若用下标，落点可以直接是
     "计划里的第 N 条真实命令"，**不需要任何占位条目**；若用标签/标记，才需要一条
     "有身份的空操作"命令。
   - **Q17-2 步进语义表**：哪些命令**自然步进**、哪些**只由事件推进**（等待类必属后者）
     ——并在此表里落实 **R10** 的连挂侧规则（交割后若停在等待命令上则强制步进）。
   - **Q17-3 失效命令的显示**：悬空引用被跳过的那条，在 GUI 里要不要可见/可删/带原因。
   - **附带的硬约束（我方可自行定，建议照此）**：**一次"到达事件"最多走一圈**——
     若整圈都没有可执行命令（全失效），**停车等待并提示**，不能无限循环推进指针。
   另：**"3 空命令"必须重定义为一条有真语义的命令**（px-patch **没有空命令原语**；
   它的 `OT_DUMMY` 只是"目标被删/等待超时"的残骸标记）。
3. **Q18「失效」分永久/暂时**（`research_pxpatch.md` §7）：**引用对象不存在** → 跳过
   （Q11）；**对象在但条件不满足**（如"还没有车在等对接"）→ **原地等待**。判据是
   "对象还在不在"，不是"现在能不能做"。
4. **Q19「前往连挂」的搜索与限制**（`research_pxpatch.md` §7）：px-patch 是全图搜索 +
   5 类限制（空车/满载、货种、路签、车厢数、车站），找不到目标 → stuck；我们要不要
   这一层？（与"demo 是否纳入连挂/解挂命令"合并研讨。）
5. **风险登记 R1~R11**（`wagon_centric_data.md` §9）：**R1 的车厢 tick 已拆分落地**
   （接线在任务 4）；**装载缓办**（demo 不做货物）；**R10 已定 / R11 押到任务 4**；其余待处理。
6. **Q12**（`Consist.wagons` 落盘措辞）——已基本澄清，只剩一句措辞。

> ⚠ **一次"到达事件"最多走一圈**这条约束是**正确性要求**（不是口味）：我们的 Q15 已定
> "走完跳回第一项"，若整圈命令全部失效，指针会在**同一帧内无限回绕**。

**三 条可借鉴**：① **"等待"是命令的执行语义**（px-patch 的 `OT_WAIT_COUPLE` 无
suspended 状态，只是每帧执行时不产生位移）——印证我们的 Q13；**但连挂交割指针后必须
显式越过该条 wait 命令**，否则接手方重新进入等待（我们记为新风险 **R10**）。
② **"解挂"是一条命令 + 一个"后段计划从哪来"的策略枚举**，而不是"产生两列车的动作"
（→ 我们的 **Q16**，✅ 已拍板方向；**三轮文档已给出他们那份枚举的完整 6 项**，见 §6.1）。③ **"执行另一个计划"用双指针**（当前表 + 自己的表与
回归格号）——将来做"计划嵌套/临时借用"时的零成本形态。

**三 条陷阱**：① **参照物本身是"计划归编组"**（单一 primary 车头、无多控制车概念）
⇒ **不能拿它论证/否定我们的多控制车遴选**；它的唯一仲裁是"谁连挂谁"，且**平局刻意
给在位者**（我们记为 **R11**）。② **他们从不"执行期跳过失效命令"**（只有每 20 天
巡检 + 新闻提示）⇒ 我们的"跳过该条、计划保留"是**自己的延伸**，Q11 的出处已就地更正。
③ **解挂后两段共享同一可变计划对象**（`AddToShared`）——与审计 B1 同型风险，**照抄
会与"计划归控制车"直接冲突**。
