# Transitional surface audit

审计范围：当前 PLAY、计划、编组和保存入口。目标是区分仍属玩家功能的入口、
有意保留的调试/测试入口，以及可以在后续切片删除的旧兼容路径。

## 当前分类

| 入口 | 分类 | 当前处理 | 后续动作 |
|---|---|---|---|
| Depot → 编组构造器 | 玩家功能 | `pygame_gui` 面板 + `consist.*` action id | 保留 |
| PLAY 左键选列车 / 右键目的地 | 玩家功能 | 普通临时行车指令；控制权标记为 `manual_takeover` | 保留，后续可改名为“接管” |
| PLAY 悬停车钩 + K | 玩家功能 | 手动连挂/解挂；计划连挂另走计划编辑器 | 保留 |
| PLAY + R 原地折返 | 玩家功能 | 停放列车手动折返 | 保留；计划折返走计划命令 |
| PLAY 节点两步放置列车 | 调试/兼容入口 | 不经过 Depot，便于测试和快速建场景 | 后续 UI 稳定后再移除；当前不得误删 |
| P/F 切换 PLAY | `P` 玩家功能；`F` 旧兼容快捷键 | 两者进入同一模式切换 | 后续可给 `F` 增加弃用提示，再移除 |
| `manual_track.geojson` 默认槽位 | 旧存档兼容 | `SaveService` 已包住写入；旧 GeoJSON 自动补版本 | 保留读取兼容；不新增平行格式 |
| `Shift+右键` 追加冻结 goto | 调试/计划过渡入口 | 仅用于观察计划执行链 | 保留至计划预览切片完成，再评估删除 |
| 终端 `print()` 诊断 | 开发诊断 | 屏内反馈与终端并行 | 按功能渐进迁移，不做一次性清理 |

## 结论

本轮没有发现应立即删除的玩家路径。最容易造成歧义的是“普通右键仍可覆盖
计划”，现在由 `TrainControlAuthority.MANUAL_TAKEOVER` 明确标记，并由
`PlanDispatcher` 在目标变化时释放计划执行租约。后续若要移除临时驾驶，需要
单独决定：右键是否改为仅编辑计划，或继续保留一个面向玩家的“接管”动作；当前
不需要做这个决策。
