## 3. 交互状态机（PLAY 模式下，编组子状态）

沿用 PLAY 现有 RTS 语义（左键选择/放置、右键下指令），只在其上加**一层车钩目标
子状态**，不新增顶层模式，不新增常驻按键负担。**定稿决策：左键永不参与解挂/连挂
操作，只负责选列车；编组操作全部由按键 + 悬停状态触发。**

```
IDLE(编组):  鼠标自由。车钩常显（内部=圆点，列车端头=方块）。
  ├─ 悬停内部车钩 → HOVER_DECOUPLE（见 §4）
  ├─ 悬停某列端头车钩 → HOVER_COUPLE（见 §5）
  └─ 其它 → 原 PLAY 行为不变（选择/放置/右键寻路）

HOVER_DECOUPLE（悬停内部车钩）:
  ├─ 车钩高亮 + tooltip「解挂 → N1+N2 节 · K/空格/回车 确认」
  ├─ K / 空格 / 回车 确认 → decouple → 回 IDLE（新前段为焦点）
  ├─ Esc / 移开鼠标 → 回 IDLE（不执行）
  ├─ 左键点击 → 忽略（左键只选列车，绝不触发解挂）
  └─ 目标列车未停车 → tooltip「请先停车」（拒绝，不执行）

HOVER_COUPLE（悬停其它列车端头车钩）:
  ├─ 端头高亮 + tooltip「连挂目标 #k（head/tail）· K 确认」
  ├─ K 确认 → 已贴住(<1m、同向、双停)直接 couple；未贴住 → 对焦点列车
  │   下达"驶向该端头车钩"的寻路指令（带连挂意图，见 §5.2/§5.4）
  ├─ 左键 / Esc / 移开 → 回 IDLE
  └─ 自己未停车 / 对方未停车 → tooltip 提示（允许：自己行驶中=下达驶向指令，
     自己已停放但距离远=先驶向；只有"到位且双方都停"才真正 couple）
```

要点：
- **解挂与连挂不再由同一颗 K 的"是否悬停"隐式区分**——解挂必须悬停**内部**车钩，
  连挂必须悬停**端头**车钩，语义由车钩类型决定，直觉一致。
- **左键不参与编组操作**（定稿）：左键永远只做选列车/放置，杜绝"点一下把车拆了"。
- K 是编组操作确认键（解挂/连挂共用）；空格/回车只是解挂的额外快捷确认。
- 预览不立即生效：解挂需确认；连挂在"到位且双方停车"前不执行。

## 4. 解挂（Decouple）规格

### 4.0 入口条件
- PLAY 模式。
- 悬停在某列车**内部**车钩上（N-1 个之一；单节列车无内部车钩，天然不可解挂）。

### 4.1 预览与提示
- 该车钩高亮放大（黄），并沿车钩垂直方向画一条短分界线示意切点。
- 屏内 tooltip（跟随鼠标）：「解挂 → {前段 N1} + {后段 N2} 节 · 左键/K 确认」。
  焦点列车悬停时不冲突：悬停内部车钩的列车既可以是焦点列车也可以是其它列车
  （现状已支持解挂任意停放列车，保留）。

### 4.2 确认与执行
确认动作（定稿：左键不参与）：**K / 空格 / 回车** 任一。
执行 `decouple_at(coupler_idx)`，成功后：
- `trains` 原位替换为 `[front, rear]`；焦点 = front。
- console 回显「Decouple #i | N→N1+N2」（现有信息保留）。
- 若 front/rear 其中一段只有 1 节且无动力（P_rated=None），仅提示不阻止
  （demo 允许玩家摆弄，后续若加"无动力单节不可独立运行"规则再拦）。

### 4.3 拒绝路径（保持现状 + 可见反馈）
| 场景 | 反馈 |
|------|------|
| 目标列车行驶中 / 信号前等待中 | tooltip + console「请先停车再解挂」 |
| `decouple_at` 抛错（越界等，理论不发生） | console「解挂失败 — {e}」 |
| 悬停到端头车钩 | 走 §5 连挂语义，不解挂 |
| 左键点击内部车钩 | 忽略车钩语义，照常走左键选列车逻辑 |

### 4.4 与调度/信号的衔接
两段都是停放实体、无 route、无预约；旧实体从 `trains` 移出后，其持有的预约由
`BlockManager.tick_reservations` 按"不在 trains 列表即清理"自动回收（既有机制，
见 `block.py` 顶部），无需在 decouple 调用处插入释放逻辑。占用 → 信号颜色由
`compute_colors` 每帧从新 trains 列表推导，自动正确。

## 5. 连挂（Couple）规格

### 5.0 入口条件
- PLAY 模式。
- 悬停**其它列车**的端头车钩（head 或 tail 均可作为"连挂目标"）。
  悬停自己列车的端头车钩 → 无操作提示「这是本车车头/车尾，请悬停其它列车」。

### 5.1 几何预判（悬停时实时计算，用于提示与指令类型）
设 A = 焦点列车，B = 悬停端头所属列车，命中端头为 b_end ∈ {head, tail}。
计算 A 的哪个端头（a_end ∈ {head, tail}）可与 b_end 配对：
- 物理配对只允许**反向端**贴一起的几何：A 车尾钩 ↔ B 车头钩，或 A 车头钩 ↔ B
  车尾钩（车头对车头 / 车尾对车尾在现实里是两个反向朝向列车的**同向**排列问题，
  demo 阶段一律拒绝——现有 `HEADING_DOT>0.9` 已隐含此约束，交互层显式化）。
- 距离与朝向实时量测：
  - `dist = |a_end.pos - b_end.pos|`
  - `aligned = heading(A) · heading(B) > 0.9`
  - `both_parked = A.is_parked() and B.is_parked()`

### 5.2 三种情形与动作
| 情形 | 判定 | 动作 |
|------|------|------|
| 到位可直接连挂 | `both_parked and dist < 1m and aligned` | K 确认 → 立即 `couple_with`（按几何选择 A 挂 B 尾 或 B 挂 A 尾） |
| 需要先开过去 | 其余情况 | K 确认 → 对 A 下达以 b_end 的 `(edge_id, t)` 为目标、带**连挂意图标记**的寻路指令；到位停车后自动执行上一条 |
| 几何上不可能 | 该 b_end 无合法 a_end 配对（如自己车头已贴对方车头） | tooltip「无法连挂（朝向不符）」，不下达 |

**自动连挂实现要点（定稿决策：凡是开到别的列车端头车钩 1m 内停车都自动连挂，
不只限于悬停过的目标，见 §9-4）**：连挂触发条件 = "本车完成一次寻路、停车
（controller 停止、route 清空）的瞬间，任意端头车钩与另一停放列车的任一配对端头
车钩距离 < 1m 且朝向一致"。不引入持久 `pending_couple` 状态——停车瞬间做一次
全 `trains` 扫描，几何满足即 couple；扫描到的第一对（按距离最近优先）就是目标，
普通右键寻路只要碰巧停在别的列车车钩旁也会连挂（这是拍板接受的取舍，见 §9-4）。
只在"停车事件帧"检测，已停放许久的列车不会被反复尝试连挂。

**车钩对齐修正（2026-09 实现时发现并修复）**：停车点是车头**转向架**，但连挂
要求车头**车钩**贴住对方尾钩——车钩在转向架前方 `head_offset`（= 首节车厢
`bogies[0].pos - coupler_1_pos`，20m 车 ≈2.5m）。若把驶向指令的目标直接设为
对方尾钩坐标，本车转向架会开到该点、车钩越过 2.5m，永远够不上 <1m 判定
（初版 e2e 实测如此）。修复：`_issue_goal_order` 新增 `stop_before_m` 参数，
在 `_apply_route_result` 里把 `remaining_to_goal` 提前 `head_offset`；调用点
（K 连挂驶向、右键吸附车钩）传入 `coupling.head_hook_offset(train)`。普通右键
寻路目标不受影响（那是"车头转向架到点"语义，玩家点哪开到哪）。

### 5.3 多候选不歧义
- 悬停 + K 的**手动连挂**：对象 = 当前悬停的端头所属列车（显式绑定）。
- **停车事件自动连挂**：停车瞬间扫描所有其它停放列车，配对端头距离最近的一对
  优先（并列时按 `trains` 顺序取第一个）。普通右键寻路只要停在别的列车端头车钩
  1m 内且朝向一致就自动连挂——这是 §9-4 拍板接受的语义（操作最少，代价是可能
  误挂，demo 阶段可接受；若后续误挂成痛点再加显式开关）。

### 5.4 拒绝与边界
- A == B：悬停自己端头 → 提示，拒绝。
- 两列其中一列是"另一列解挂出来的前/后段"且位置重叠（尚未移开）→ 物理上距离
  < 1m 且同向，直接 couple 会恢复原列——**允许**（等效撤销一次解挂，是 feature）。
- 信号/block：连挂只在停车后执行，无 route，无预约冲突；连挂后新实体由调度层
  正常接管。
- 连挂目标在 5 m 外时右键仍走普通寻路？——**不**：悬停端头车钩后右键只表示
  "驶向并连挂"，5 m 只是吸附阈值不是距离限制；指令可达性交给 `find_path_from_point`
  判定，不可达则 console「不可达」，不留 pending。

### 5.5 信号豁免（2026-09 追加，验收时发现的功能缺口）✅ 已实现

**问题**：连挂驶向、解挂后分离驶离，本质都是"列车要开进/开出**被另一列车占用
的受保护闭塞区间**"。信号系统的物理占用检查（`dispatcher.tick` 的
`others_occupied`）会把这些区间判红灯，列车永远够不到目标（连挂），或在前段
驶离时因后段仍占共享边而 hard_stop 锁死（解挂）。**本仓库无碰撞判定**，因此
不需要 OpenTTD fork 的"旁路撞车判定 + 把撞车重定义为连挂"——只需对"编组作业
的配对列车"放开信号闸，授权边界仍 clamp 在车钩处（§5.2 的 stop_before 已保证
车钩对齐、不压线）。

**实现（思路 2 窄化版，采纳用户拍板）**：

1. **绕开的逻辑只有一处，且显式标注**：`model/dispatch.py::TrainDispatcher.tick`
   构造 `others_occupied`（其它列车物理占用的 edge 集合）时，**排除**两个豁免
   集合——本车的 `couple_approach_partner`、以及"与本车共享至少一条 occupied 边
   的 `split_sibling`"。其余判定全部保留：
   - `reserve_path`（预约表冲突）**不绕开**——若第三方也预约了目标边仍会被拦；
   - `compute_colors`（信号灯红绿）**不绕开**——区间被占用时信号仍显示红灯
     （视觉上就是"冒进信号"，符合 OpenTTD 语义）；
   - `_walk_frontier`/授权边界计算**不绕开**——授权边界仍到下一信号，只因
     `update()` 制动目标 = `min(remaining_to_goal, authority)`，到车钩的
     `remaining_to_goal` 更近，所以车停在车钩前（运动控制无需改动，用户已确认
     "驶到 edge 途中点"可靠）。

2. **两个豁免标记**（`TrainEntity` 上的运行时字段，随指令生命周期）：
   - `couple_approach_partner: TrainEntity | None`——下达"驶向某列车端头车钩"
     的连挂指令时写入目标列车；用于 A 与 B **不共享边**的情形（A 在保护区外、
     B 占着目标区间）。指令结束（停车）后由 `_merge_couple`/取消清除。
   - `split_sibling: TrainEntity | None`——`decouple_at` 返回的 front/rear 互指
     `split_sibling`；用于解挂后两段**共享边**的情形。豁免条件是"共享边"在
     `dispatch` 每帧即时判定，两段驶离到不再重叠即自动失效，无需显式清除。

3. **安全网**：豁免只影响"本车 vs 那一列配对车"的物理占用；配对车若在接近途中
   移动/被解挂/消失，其占用集合变化后豁免自然缩小（因为豁免按对象引用 + 共享
   边动态判定，不是按边 id 静态放行）。第三方列车不豁免。

**绕开清单（供维护）**：
- `model/dispatch.py` `tick()`：`others_occupied` 排除 `train.couple_approach_partner`
  与共享边的 `train.split_sibling` 的 `occupancy.occupied`。**仅此一处**。

### 7.1 模型层（现有，补充断言）

  原样 couple 回来总长/头位置不变（已在草稿验证过，固化成测试）。

### 7.2 controller 层端到端（新 `tests/test_couple_ui.py`，可脱离 GUI）
通过构造 `GameLoop`（SDL dummy driver）或直接调用其方法，驱动：
1. 解挂：停放 4 节列车 → 悬停 idx=1 车钩 → K 确认 → trains 变成 2+2，焦点=front，
   位置连续；单节列车悬停无内部车钩 → 无操作。
2. 解挂拒绝：行驶中列车悬停其内部车钩 + K → 拒绝、状态不变；悬停内部车钩时
   左键 → 只走选列车逻辑，不解挂。
3. 连挂（即刻型）：两列停放且 <1m 同向 → 悬停 B 端头 + K → 立即 couple，车厢数
   相加。
4. 连挂（停车事件自动）：两列停放但距离 >1m → 对 A 下达驶向 B 端头 (edge_id,t)
   的普通右键寻路 → 跑 dispatch 帧到 A 停放 → 停车事件帧自动 couple 成 1 列。
5. 拒绝：自己端头 / 朝向不符 / A==B（悬停自己）→ 不 couple、状态不变。
6. 多候选：三列在场，停车瞬间只与距离最近的列车连挂。
7. 回归：普通右键寻路停在不挨车钩处 → 不自动连挂，正常停放。
8. 回归：已停放许久的列车（非停车事件帧）旁停新列 → 只发生一次连挂，不反复。

### 7.3 人工验收脚本（给用户跑）

自动连挂 → 再解挂 → 全程观察视觉提示与 console。
