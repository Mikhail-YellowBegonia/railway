## 0. 一句话

把"**去哪里**"从"逐次人工下达 + 运行时寻路"升级为"**计划（条目 + 指针）**"。
编辑阶段可借助寻路生成候选路线，但确认条目时必须冻结为**完整的有向边序列**；
执行阶段只消费这条固定路线，**不得再跑 Dijkstra 或按锚点补全**。锚点与控制点是
创建/解释固定路线的编辑元数据，而不是运行时的替代路线。所有引用落在图上已有的物理
要素上；删除严格拒绝，切分只能经原子改写后放行。

> **2026-09-15 实施口径修正**：原稿 P2 的 `resolve_plan_item()` 会把锚点之间交给
> Dijkstra 补全。这是有效的"路点计划"，但不符合当前 demo 的"预定义路径替代实时
> 寻路"目标。P2 作为**编辑期路径构造器**保留；从 P3 起，运行期的唯一权威路径是
> 冻结后的 `FixedRoute`。本节与 §3.1 的 P3/P4/P5 以此为准。
>
> 边界：PLAY 的普通右键与既有 K 键手动调车仍可作为**非计划的临时指令**使用
> Dijkstra，确保既有调试与连挂交互不回归；本限制针对**计划条目的执行**。P7 的
> `goto_couple` 进入计划后同样必须走冻结接近路线。

## 2. 数据模型（Q23-1 定稿）

### 2.1 结构

```python
# 锚点：硬约束 = "必须经过这个节点"；exit_edge_id 给定时 = "并且从这条边离开"（= 控制点）
Anchor = (node_id: int, exit_edge_id: int | None)

# 目标：沿用现有 TrainEntity.goal 格式 ——(edge_id, t, direction)
#       允许停在边中途（右键点任意点就是这个语义）⇒ 站台停靠 = 目标 t 落在站台段内
Goal   = (edge_id: int, t: float, direction: int)

PlanItem = {
    command: Command,          # 携带"逻辑"的唯一层
    goal: Goal | TrainRef,     # 终点（连挂类条目指向"列车 + 端头"）
    anchors: list[Anchor],     # 可选：路径限定（有序、硬约束）
}

Plan = { items, pointer, loop_route, has_wrapped }
# 首条 fixed_route = 首次启动位置→第一目标；loop_route = 末目标→第一目标。
# 指针在控制车（Q14）；走完回绕到 0（Q15）。
```

**要点**
- **锚点必须是图上已有的节点** ⇒ **永不切边**（与"图拓扑不变量"一致：只有基础设施编辑改图）。
- **终点可以是边中途**（`t`）⇒ 站台停靠不需要新实体。
- **控制点 = 锚点的一个字段**（道岔处指定出口），不是独立概念 ⇒ 数据结构只有一套。
- 引用**全部落在节点/边上**（Q22-2）⇒ 删除保护可直接复用现有按 edge 的锁定机制。
- **demo 里引用用内存 id（`node_id`/`edge_id`）即可**——因为 Q23-6 定了"不落盘"，
  计划不跨会话存活，**几何锚定（`session.py` 那套）推迟到计划落盘立项时再做**。

### 2.2 命令集合（Q23-7 ⇒ demo 三条）

| 命令 | 语义 | 目标 | 步进方式 |
|---|---|---|---|
| `goto`（前往） | 走到目标点并停稳 | `Goal`（边+`t`+方向），可带锚点/控制点限定 | **自然步进**（停稳即步进） |
| `goto_couple`（前往连挂） | 开到指定列车的指定端头车钩并**完成连挂** | `TrainRef`（目标列车 + 前/后端） | **事件步进**（连挂完成事件） |
| `wait_couple`（等待连挂） | 原地（站台内）等待别的列车来连挂 | 无 | **只由事件推进**（被连挂时，R10：交割后若停在等待命令上则**强制步进**） |

**无跳转命令**（Q23-8）：循环 = "走完回绕第一项"；等待类的恢复落点由**事件**直接给定
（⇒ 用户示例里那条"3 空命令"**不再需要存在**，问题自然消解）。

### 2.3 步进语义表（Q17-2 **据此封口**）

| 命令 | 谁推进指针 | 触发条件 | 备注 |
|---|---|---|---|
| `goto` | 列车（到达事件） | 停稳（幂等，复用 `moving_before`/`just_stopped` 事件帧） | 硬约束锚点解析失败 ⇒ 按 §4.4 失效语义，**不换路** |
| `goto_couple` | 列车（连挂完成事件） | 物理对接成功 → 合并 → **越过停在等待命令上的指针**（R10） | 连挂后计划由**遴选**胜出的控制车执行（Q5/Q6，**不交割计划**） |
| `wait_couple` | 外部事件（对方车连挂上来） | `Couple()` 完成 | 等待期间**不是挂起**：每帧照常执行、只是不产生位移（Q13） |

**硬约束（我方定的正确性要求）**：**一次到达事件最多走一圈**——若整圈都无可执行命令
（如全部失效），**停车等待并提示**，不得在同帧内无限回绕（Q15 的"回绕"必须配这条）。

#### P3a / P3b 固定路径计划接入列车（**P3b 是第一个"有行为"的阶段**）

**实现要点**
- **P3a 先冻结路径，不接行车**：增加 `FixedRoute`（完整、有序的
  `tuple[DirectedEdge, ...]` + goal/停车距离所需元数据）。`PlanItem` 的固定路线
  是运行期权威；锚点/控制点只保留为可解释的创建元数据。`model/plan_path.py` 的
  Dijkstra 解析器只可用于**编辑预览、测试构造和临时调试入口**，确认后把结果复制为
  `FixedRoute`，执行链路不得调用它。
- **P4 是 P3b 前置，不得跳过**：现有 `RailNetwork.split_edge_at()` 直接删旧边再建
  两条新边；而 `Editor` 的三个调用点和信号放置各有一个调用点，当前没有全局变更事务。
  在固定路线接线前必须建立协调器，禁止"轨道已改、引用尚未改"的中间状态。最小安全
  策略如下：
  - 删除/合并：任一受影响边或节点被 `FixedRoute`、锚点/控制点、运行 `route`、
    `occupied` 引用即拒绝；
  - 切分：仅在旧边**不被任何车身 `occupied` 覆盖、也未放置信号**时放行。提交后在
    同一个调用栈中把旧有向边 `(X,+)` 改写为 `(X1,+),(X2,+)`，`(X,-)` 改写为
    `(X2,-),(X1,-)`；同时改写运行 `route` 和每个 `FixedRoute`，并更新 goal 的局部 t；
  - 不能做全量改写的拓扑操作先拒绝，不得依赖 `SignalTable.prune_missing()` 静默丢信号。
  这比尝试 Transport Fever 2 式的全图适配窄得多，但保证"未切断的固定路线保持完好"。
- **P3b 行车接线**：落点为 `Wagon.plan: Plan | None`（**车厢域数据**，不碰
  `WagonConfig`，Q3/Q1）；新模块 **`model/plan_dispatch.py`**（**不动
  `dispatch.py`**，信号预约/授权那套保持原样）。
- 每帧：编组**遴选**控制车（`have_control` 的车里取 `(-priority, wagon_id)` 最小者，
  Q5/Q6，不查重）→ 取 `plan.current()` → 从它的 `FixedRoute` 投影成 `route`/`goal`。
- ⚠ **投影必须带激活令牌而非寻路缓存**：只在"当前条目首次激活 / 指针改变 / 固定路线
  被 P4 改写"时下达一次 `assign_route`；信号等待时必须保留原 route，绝不可覆写。
  **运行时不得跑 Dijkstra**。当前车头若不在固定路线的可消费位置，标为暂时不可执行并
  原地等待，不能偷偷重算一条连接路。
- **到达事件步进指针**（Q14）：复用 `GameLoop.run()` 已有的
  `moving_before`/`just_stopped` 帧；**幂等**（每"到站"只步进一次）；
  **单一步进者**（只有当前遴选胜出、且正在执行该计划的那列车能步进）。
- 步进语义按 **§2.3**：`goto` 自然步进；`wait_couple` **不**自然步进；`goto_couple` 由
  连挂事件推进（P7）。**每步进一次指针 = 一次"到达事件"** ⇒
  **一次到达事件最多走一圈**：整圈都无可执行条目 ⇒ **停车等待并提示**（不得同帧回绕死循环）。
- 失效（§4.4）：**永久失效**（引用对象不存在）⇒ 该条**跳过**（计划保留），
  并在"这一圈"内继续找下一条可执行的；**暂时不可用** ⇒ **原地等待**（`is_holding` 语义）。
- **R11 回归断言**：遴选在**连挂/解挂往返后**结果稳定；同编组内执行权易主的情形
  要有明确断言。计划随车厢对象自然保留，绝不在 couple/decouple 时复制、合并或搬移。
  合并后胜出计划若不能从合并列车当前车头消费固定路线，必须安全等待并给出原因；
  不能为"继续跑"而重新寻路。P7 的验收须另覆盖一组能连续消费的正常场景。

**验收标准**
1. headless：给列车挂两条**已冻结**的反向 `goto` 路径 ⇒ 连续 tick 后**指针回绕**、
   列车持续往返（断言位移推进、指针循环、执行期间 P2/Dijkstra 调用计数为 0）；
2. 永久失效：删掉某条目的目标节点 ⇒ 该条被跳过、**计划保留**、不崩、有提示；
3. 全失效整圈 ⇒ **停车等待**（断言一次到达事件内指针最多走一圈，不会死循环）；
4. P4：删除固定路径任何边/节点被拒绝；切分一条未占用、未设信号的固定路径边后，
   路径和运行 route 都被改写，仍连续且不触发 KeyError；占用/设信号边的切分被拒绝；
5. **未挂计划的列车行为与今天逐字不变**（全套既有回归全绿）；
6. 遴选：`priority` 大者胜、相同则 `wagon_id` **取小**者胜（断言）。
7. 连挂/解挂：计划不搬移；遴选结果稳定；无法从合并后车头消费路径时安全等待、有原因、
   不崩且不寻路。

✅ **已拍板临时调试入口**：`Shift + 右键` 给选中、停放列车**追加一条冻结的** `goto`
条目；普通右键行为不变。连续追加时，下一个条目的构造起点是上一冻结条目的终点，而不
是屏幕上仍停在原处的列车，故两次点击可预先构造往返环。该入口只服务 P3b 人工验收，
P5 正式编辑交互落地后移除。

#### P4 拓扑变更防火墙（固定路径执行前置）

**实现要点**
- 准入判断放 **`GameLoop` 的拓扑变更协调器**（DELETE 继续复用
  `_rail_delete_blocked_reason`）；`Editor` 保持对列车/计划零耦合。不可只在变更后
  `prune_missing`，因为那是丢失基础设施，不是保持路径。
- 锁定集合来自计划侧纯函数，至少包括：**FixedRoute 的全部 edge**、锚点 `node_id`、
  控制点 `exit_edge_id`、终点 `(edge_id, t)`；并与当前 `occupied`/运行 `route`/信号
  引用取并集。
- **切分受控放行 + 原子改写**：`split_edge_at` 的调用点共 4 处
  （`controller/editor.py` M1/M2 path-snap 截断 3 处、`GameLoop._signal_left_click` 1 处）。
  不能在切分**之后**才随意补钩子；必须由统一协调器在提交前检查、提交后同步改写。规则：
  - 旧边 `X` 在 `t0` 处切成 `X1=[0,t0]`、`X2=[t0,1]`；
  - **锚点（节点）不受影响**（节点 id 不变）；
  - **控制点**"从 X 的 a 端离开" ⇒ 映射到 `X1`；"从 X 的 b 端离开" ⇒ 映射到 `X2`
    （语义 = "从这个节点走这条边离开"，与子边一一对应）；
  - **终点 `(X, t, dir)`**：`t < t0` ⇒ `(X1, t/t0, dir)`；否则 `(X2, (t−t0)/(1−t0), dir)`。
- **节点合并**（DELETE 二度节点会**删除**该节点）也要纳入：若被删的是计划引用的
  锚点，或任一相邻边在 `FixedRoute` / 运行路径 / 信号表中 ⇒ **一律拒绝**。不把它
  降级为永久失效，因为这是玩家可预防的编辑操作，而非外部数据损坏。

**验收标准**（拓扑协调器 + `tests/test_delete_guard.py` 扩展）
1. 计划引用的边 ⇒ 拒绝删除（边保留）；
2. 计划引用的节点（锚点）⇒ 拒绝删除 / 拒绝合并；
3. 在被引用但未占用、未设信号的边上触发切分 ⇒ **放行**且完整改写；在 occupied 或
   已设信号边上切分 ⇒ **拒绝**，网络、信号、运行路径和固定路径都保持不变；
4. 自由路段照旧可删。

#### P5 最小交互（**固定路径计划编辑**）

**实现要点**
- **必须是明确的叠加态**（进入/退出）：PLAY 的左键既有语义是"选列车/放置"，
  不能直接复用。候选键 **`P`**（PLAY 下切换"计划编辑"叠加态；BUILD 里 `P` 是按住式
  平行吸附，语义不同、不冲突）。**进入条件 = 选中列车 `is_parked()`**（Q23-5），
  否则拒绝并提示原因。
- 交互流（Q22-4"点几下"）：选中列车 → 进编辑态 → **左键点节点 = 追加锚点**
  （`Backspace` 退一步）→ **点道岔锚点后再点一条出边 = 控制点** →
  **左键点边上任意点 = 设终点** → **`Enter` 确认**生成条目并**追加到计划末尾**
  （确认即生效，Q23-5）→ `P`/`Esc` 退出前必须冻结“末条→第一条”闭环
  （未确认草稿丢弃；闭环失败则保持编辑态）。
- 渲染：编辑态画**候选锚点序列**（节点标记 + 顺序号）与**编辑期解析出的路线**；
  `Enter` 后明确标记为冻结路径。解析失败 ⇒ 红 + 打印原因（P2 已给出原因字符串）。
- HUD 文本显示**当前条目 / 指针位置 / 计划长度**（不做面板 GUI，Q22-4）。
- ⏳ **待确认（最低编辑能力）**：Q22-4 说"不做面板 GUI"，但"**删除条目 / 清空计划**"
  是最低限度的编辑能力——建议编辑态下 `Delete` 删除当前条目、`Ctrl+Delete` 清空计划。

**验收标准**
1. **真人在 GUI 里点两下 ⇒ 列车自动往返循环**（"跟着计划走"的最直观验收）；
2. 行驶中的列车进入编辑态被拒绝并提示（`is_parked()` 门禁）；
3. 解析失败的条目**可见 + 标红 + 带原因**（Q23-3）。

#### P7 连挂条目（最简形态）

**实现要点**
- `goto_couple` 也必须携带**冻结的接近 `FixedRoute`**；`TrainRef(wagon_id, end)`不是
  寻路目标，而是到站时的对接校验对象。目标车钩只允许在固定路线末边、预定到达方向上
  做小范围 `t` 偏移；目标已移动到其它边/方向 ⇒ **暂时不可用，原地等待并提示**，禁止
  为追逐目标重新寻路。`stop_before_m = head_hook_offset`。
- "该车厢现在在哪列车上"：遍历 `self.trains` 的 consist 找 `wagon_id`；找不到 ⇒
  **永久失效**（Q23-2）。
- 连挂完成 ⇒ 走现有物理对接 + `couple_with`（要求双方停放）；**合并后按 R10
  强制步进**（接手方指针若停在 `wait_couple` 上则越过）；**计划不交割**（Q5/Q6/Q16 补注）。
- 含 `goto_couple` 或 `wait_couple` 的计划是**一次性事件链**：编辑退出不生成
  `loop_route`，执行完最后一条后指针停在尾后、列车停车并提示“计划已完成”。不能把纯
  `goto` 的 `n→1` 接缝语义套用到连挂事件上；后续若需要循环调车，须先单独设计事件链
  的重置条件与目标再绑定规则。
- `wait_couple` 不要求站台实体，只要求零速、原地等待，并在 HUD 标注“等待连挂”。

**验收标准**
1. A 的计划 = [前往连挂(B 端头), 前往 C]、B 的计划 = [等待连挂, 前往 D]：
   连挂 → 合并 → **由遴选胜出的控制车继续跑它自己的计划**（A/B 计划都不搬移）；
2. 解挂后两段**各自继续自己的计划**；
3. 目标车厢被解挂/消失 ⇒ 该条**永久失效**（跳过 + 标红），另一条计划不受影响；
4. 连挂侧 R10：接手方不得重新进入等待（**永不前进**的反例要有断言）。
5. 编辑器可正常确认含连挂条目的计划；最后一条完成后不得回绕或调用寻路，而应停车并
   给出完成状态。

#### P10 动态连挂候选（**demo 后，不插入 P7**）

   占用状态；
2. `goto_couple` 用显式筛选条件和稳定 tie-break 选择一个候选；

- 节点边界允许两种拓扑等价表示：上一条入边末端与下一条出边起点是同一物理位置。
  制动器停在节点前 `POSITION_EPSILON_M` 内时，执行层可在验证共享节点与合法转向后
  直接接上冻结出边，并把厘米级余量计入下一条剩余距离；不移动列车、不切边、不寻路。
- `FixedRoute.start_offset` 是创建时的距离记账基准，不是永久停车检查点。计划循环回到
  冻结路径内任一有向 edge 的合法 `t` 时，可从实际 occurrence 消费固定路径后缀并重算
  剩余距离；若已经沿该方向越过目标才拒绝。车头 edge/t/direction 必须由运动学原子
  查询，不能把 `edge_at()` 与 `occupied[-1]` 的方向拼成一个可能不存在的起点状态。
- `goto` 到达且车头确实落在条目目标时只步进一次；永久失效条目最多环扫一次后跳过，
  全失效计划停车等待。固定路线起点不能从当前车头消费时安全等待，不折返、不补路。
  `wait_couple` 与 `goto_couple` 在 P3b 阶段保持等待；P7 已补齐其事件推进。

## 4. 关键技术设计（**P2 已按此实现**；含实现期发现）

### 4.1 解析（P2）

1. **逐段寻路**：切成 `起点 → 锚点₁ → … → 目标` 若干段，每段用现成的
   `find_path_from_point`（全仓唯一跑 Dijkstra 的入口，**不切边**）。
2. **"经过节点 N"**：搜索状态本来就有向边 ⇒ 段终点 = "**到达 N 的那些有向边**"。
   这是**多目标**寻路——本图极小（4 个道岔），**先按"N 次单目标调用取最小"实现**
   （`poi.md` O7 记的同一件事），不必改 `find_path`。
3. **控制点（道岔选出口）**：约束"到达边 X → 离开边 E"满足 `turn_allowed(N, X, E)`；
   对每个锚点枚举**合法转向对**（本图每道岔 4 个），**逐锚点 DP（Viterbi）**取最优——
   相邻两段独立算完再拼会出现"拼不上"的非法转向，这一步正是为了排除它。
4. **失败即失败**（Q22-3 硬约束）：任一段不可达 ⇒ 整个条目解析失败 ⇒ 按 §4.4 处理。
5. **产出契约与现有链路一致**：`(route: list[DirectedEdge], remaining_to_goal: float)`，
   直接喂 `TrainEntity.assign_route`（⇒ **执行层零改动**）。
6. ⚠ **实现期发现（必须记住的坑）**：`find_path` 里有一个 `force_leave` 分支
   （"起点有向边 == 目标有向边"时，为免把"原地不动"当成到达，**强制先离开再绕回来**）。
   而本模块的段终点语义是"**到达该有向边的 head 节点**"⇒ 当锚点／控制点**正好落在
   起点节点上**（`arrive == start_directed`）时，列车已经在这条边上朝它走，
   这一段**应当是"就这一条边"**；直接交给 `find_path` 会被判成"必须绕一大圈"
   甚至不可达。`_leg()` 因此对"同边同向"做了特判
   （`tests/test_plan_path.py` ③ 就是这个用例）。

### 4.2 保护（P4）

- **删除**：`_train_locked_edges()` 同构地扩成"列车占用/预约 ∪ **计划引用的节点与边**"，
  拒绝并提示（与 DELETE 保护同一处准入判断，**`Editor` 仍零耦合**）。
- **切分**：放信号 / 建造 Path-snap 会 `split_edge_at`（不改几何）⇒ **放行**，
  但要在切分后用"覆盖关系"把计划里对被切边的引用**机械改写**为其子边
  （删除被切边时同理——但删除是被拒绝的，所以只会遇到切分）。
- 目标被删 ⇒ 引用永久失效 ⇒ §4.4。

### 4.3 交互（P5）

- 仅 `is_parked()` 可编辑（Q23-5）；锚点序列**按点击顺序**追加、可回退一步；
  道岔锚点在选中后可**再点一条出边**成为控制点；确认即生成/更新条目并**立即生效**。
- **不做面板 GUI**（Q22-4）；计划的可视化 = 轨道上的锚点标记 + 高亮路径。

### 4.4 失效语义（Q23-2/Q23-3）

| 情形 | 判据 | 行为 |
|---|---|---|
| **永久失效** | 引用的对象**不存在**（节点/边被删；目标列车已解挂消失） | 该条目**跳过**（Q11：计划保留），**GUI 标红 + 原因**，**不自动删除** |
| **暂时不可用** | 对象**在**，但条件不满足（还没有车在等连挂、目标车正被别的车连挂） | **原地等待**（命令本义），GUI 提示在等什么 |

⇒ 判据是"**对象还在不在**"，不是"现在能不能做"（外部对照见 `research_pxpatch.md` §7）。
