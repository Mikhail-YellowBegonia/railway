## 2. 数据模型（由 Q22-5 + 现有 `goal` 格式推出，**待 Q23-1 确认**）

```python
# 锚点：硬约束 = "必须经过这个节点"；exit_edge_id 给定时 = "并且从这条边离开"（= 控制点）
Anchor = (node_id: int, exit_edge_id: int | None)

# 目标：沿用现有 TrainEntity.goal 格式 ——(edge_id, t, direction)
#       允许停在边中途（右键点任意点就是这个语义）⇒ 站台停靠 = 目标 t 落在站台段内
Goal   = (edge_id: int, t: float, direction: int)

PlanItem = {
    command: Command,          # 携带"逻辑"的唯一层（demo：goto；等待类待 Q23）
    goal: Goal,                # 终点
    anchors: list[Anchor],     # 可选：路径限定（有序、硬约束）
}

Plan = { items: list[PlanItem], pointer: int }   # 指针在控制车（Q14）；走完回绕到 0（Q15）
```

**要点**
- **锚点必须是图上已有的节点** ⇒ **永不切边**（与"图拓扑不变量"一致：只有基础设施编辑改图）。
- **终点可以是边中途**（`t`）⇒ 站台停靠不需要新实体。
- **控制点 = 锚点的一个字段**（道岔处指定出口），不是独立概念 ⇒ 数据结构只有一套。
- 引用**全部落在节点/边上**（Q22-2）⇒ 删除保护可直接复用现有按 edge 的锁定机制。

## 4. P2 的关键技术设计（**实现前应确认**）

**问题**：一条"锚点序列 + 目标"如何解析成 `route`，且**不切边、不改图**？

1. **逐段寻路**：把整条路径切成 `起点 → 锚点₁ → 锚点₂ → … → 目标` 若干段，
   每段用现成的 `find_path_from_point`（全仓唯一跑 Dijkstra 的入口，不切边）。
2. **"经过节点 N"怎么表达**：搜索状态本来就有向边 ⇒ 段终点 = "**到达 N 的那些有向边**"
   （即所有"朝向 N"的入射边）。这是**多目标**寻路——本图极小（4 个道岔），
   **先按"N 次单目标调用取最小"实现**（`poi.md` O7 记的同一件事），不必改 `find_path`。
3. **控制点（道岔选出口）**：约束"到达边 X → 离开边 E"必须满足 `turn_allowed(N, X, E)`。
   对每个锚点枚举**合法转向对**（本图每个道岔 4 个），**逐锚点做 DP**
   （每个锚点保留"到达边→离开边"组合的最优代价，顺序合并 = Viterbi），
   规模极小且**精确**（相邻两段独立算完再拼会出现"拼不上"的非法转向，
   这一步正是为了排除它）。
4. **失败即失败**（Q22-3 硬约束）：任何一段不可达 ⇒ **整个条目解析失败**，
   交给 Q23-2/3 定的失效语义处理，**不换路、不绕行**。
5. **产出契约与现有链路一致**：`(route: list[DirectedEdge], remaining_to_goal: float)`，
   直接喂给 `TrainEntity.assign_route`（⇒ 执行层零改动）。
