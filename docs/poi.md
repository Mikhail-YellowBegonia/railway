## 1. 三类基本 POI（用户 2026-09-10 提出）

| 类型 | 定义 | 连接数限制 | 主要代表 | 状态 |
|---|---|---|---|---|
| **无向点** | 单个 `Node` | **= 2** | **Waypoint（路点）** | 远期 |
| **有向点** | `Node` + `Edge`，**从 edge 指向 node**（edge 只给方向不给长度） | **≤ 2** | ⚠ **未知**（用户原话："不知道代表什么"） | **最小可行范围** |
| **路段** | `Simple_Segment`（一串 Edge 的集合） | — | **站台 / 站线** | 远期 |

> "有向点"在 GIS 视角上是一种**带额外属性的点要素**；它能表达 `(edge_id, t)` 表达
> 不了的东西——尤其是 **"有方向的停车点"**（进站方向、停车位置、站台末端）。
> 有向点"代表什么"仍未知，不影响它先落地（见 §4）。

## 2. 建筑 = POI 的集合

- **一切建筑都是各种 POI 的集合**。
- 例：**一个火车站 = 很多站台的集合**——可能是 **4 个"路段"代表 4 个站台**。
- 用户指出这与 **OSM 的做法很像**（点要素 + 关系/集合组织要素）。

## 3. 调度计划如何指向 POI（解析链）

```
调度计划条目（指向建筑）
      ↓  解析 / 分配
建筑（POI 集合）
      ↓  选中其中某个 POI
POI（有向点 / 无向点 / 路段）
      ↓  唯一确定
node（或"途中点"）
      ↓
现有寻路方法（find_path_from_point / find_path）
```

- **远期**：计划条目指向**建筑**，由"解析与分配"落到具体 POI。
- **MVP**：**计划直接指向 POI**（跳过建筑层），见 §4。

## 4. 最小可行范围（用户 2026-09-10 拍板）

1. **只做"有向点"**这一种 POI。
2. **调度计划直接指向 POI**（不做"计划→建筑→POI"的解析层）。

无向点（Waypoint）与路段（站台/站线）、以及建筑层，均属**远期**。

## 5. ★ 与现有寻路的适配（2026-09-10 核对结论）

> 用户在方案里提出一个挑战与一个不优雅的解法：
> "**Dijkstra 只能导航到 node，不能要求从点的固定方向到达。我们可以通过编辑成本图
> 来解决（向到达 node 但方向错误的边挖掉），不优雅但有效，期待更好方案。**"
>
> **核对结论：本仓库的寻路状态空间本来就是"有向边"，不需要挖成本图。**

### 5.1 有向点 ≡ `DirectedEdge`，现有 `goal_directed` 已精确锁定到达方向

- `model/pathfinding.py::find_path(..., goal_directed: DirectedEdge | None)`：
  `_is_goal(cur)` 在给定 `goal_directed` 时是 **`cur == goal_directed`**——
  **必须精确走到那条有向边**才算到达（`goal_directed=None` 时才是"任意方向到
  目标节点"，那是**无向点**的语义）。
- `find_path_from_point(..., goal_direction: int)` 是**必填**参数，并把
  `goal_directed=(goal_edge_id, goal_direction)` 传下去；`end_offset` 按方向计算。
  文档字符串里写着这正是为消除"到达方向歧义"（历史上方向不定会让 `end_offset`
  算错、停车位置轻微偏移）。
- ⇒ **"从固定方向到达"已经由搜索的状态空间保证**：方向不对的来路根本不会命中
  目标，不需要"把方向错误的边挖掉"。
- 现成助手：`model/pathfinding.py::_directed_from(network, edge_id, node_id)`
  （`controller/game_loop.py` 放置列车时已在用）——**有向点 → `DirectedEdge` 的
  转换就是它**：取那条 edge 中**以 POI 的 node 为 head** 的方向。

### 5.2 三类 POI 与现有能力的对照

| POI 类型 | 落到现有接口 | 现状 |
|---|---|---|
| **有向点**（MVP） | `goal_directed = _directed_from(net, edge, node)` + `goal_t` | ✅ **现成可用** |
| 无向点（Waypoint） | `goal_directed=None`（任意方向到目标 node 的分支） | ✅ 已支持（`find_path` 默认分支） |
| 路段（站台/站线） | 段内**每个有向边**各求一次路径取代价最小（多目标） | ⚠ **无现成入口**；段内边数很小，用 N 次 `find_path_from_point` 取最小即可（先求正确，不提前优化） |

### 5.3 两个必须补的表达（很小）

1. **停车点 `t`**：POI 的最小单元（node + edge）只给**方向**与**哪个 node**；
   而"有方向的停车点""站台末端"要停在哪个位置，需要 POI 带上 `t`（默认 = 到
   node 端，即 `t=1.0`/`0.0` 按方向折算）或直接支持"途中点"。
   ⇒ POI 解析出的目标 = **`(edge_id, t, direction)`**，与现有 `goal` 三元组同构。
2. **多目标（路段）**：`find_path_from_point` 只接受**单个** `goal_directed`。
   路段的"停在段内任意处"需要枚举段内边取最优（或给寻路加多目标入口）。

### 5.4 与"转向许可"的交互（顺带确认语义正确）

`turn_allowed` 由几何自动推断（前进半平面）。若某个站台的进站方向在道岔处被
`turn_allowed` 禁止，那么 `goal_directed` 会**直接报不可达**——这正是想要的语义
（"不能从那个方向进站"而不是"从反方向倒着进了站"）。

## 6. 归属与引用完整性

- **归属**：POI 属 **C 桶「基础设施侧」**——挂在 `node`/`edge` 上，**随轨道
  编辑与落盘**（与信号同一桶）。既不是车厢域数据也不是编组运行期状态。
- **引用完整性**：计划条目引用 POI，而 POI 会随轨道编辑被删除 →
  **按 `docs/wagon_centric_data.md` Q11 已拍板的语义处理：该条命令跳过执行、
  计划仍保留**（执行期跳过，不是编辑期拒绝）。
  信号已有同类"悬空引用"处理（`SignalTable.prune_missing`），但 POI 的策略**不同**
  （信号是自我清理，计划是跳过执行）——两者不要混为一谈。
